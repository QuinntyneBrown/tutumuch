Accessibility

WCAG 2.2 AA is the floor for every component and page: one h1, landmarks, visible labels, named icon buttons, alt text including Tilly’s, AA contrast and a visible focus ring.

WCAG 2.2 AAStatus: stablePage guidelines

Overview

TuTuMuch is used by parents in a hurry, grandparents with larger text and families on old phones. The page guidelines (section 12) and L2-096 make these rules testable: Playwright checks every routed page for one h1, one logo, labelled icon buttons, alt text, at most one Tilly and no inline hex or gradient; axe runs in CI (L2-064).

Perceivable

  • Text ≥ 4.5:1, UI edges and focus ≥ 3:1, every pair checked in both themes (contrast pairs). White on raspberry only at 16px semibold or larger; lilac never as text.
  • Every image has meaningful alt text; decorative images use alt="". Tilly’s alt text names her and what she is doing: “Tilly kicking a soccer ball” (Tilly).
  • Status is colour, icon and text; condition badges carry their label; Sold says “Sold”.
  • Reflows to 320px; rem sizes.
  • Decorative SVG (the mark, icons) hidden; meaningful ones labelled.

Operable

  • Full keyboard support with a logical tab order; dialogs trap focus and close on Esc.
  • One focus style everywhere: a 2px raspberry ring with a 2px offset (--shadow-focus) on :focus-visible.
  • Every icon-only button has an aria-label.
  • Sticky bars never cover focus.
  • Targets ≥ 24px, primary mobile targets ≥ 44px.
  • Skip link on every page.
  • Motion respects reduced motion; nothing animates on load.

Understandable

  • Every field has a visible label, not just placeholder text; errors appear next to the field and link from a summary.
  • Plain language: what happened and what to do.
  • Destructive actions confirm and say what is lost.
  • One primary action per view.

Robust

  • Semantic HTML: header, nav, main, section, footer, with exactly one h1 and no skipped heading levels.
  • Native elements first; ARIA follows the APG patterns named on each page.
  • Loading containers set aria-busy; toasts and the reservation timer use live regions.
  • One logo link per page (the mark in the header is inside it; the footer mark is not a link).

Testing

  • check_contrast.py and check_design_system.py on every design-system change; axe and the page-guideline checks in CI.
  • Keyboard pass on a page, a dialog and a toast; screen reader pass on the closet, the sell form and checkout.
  • Zoom 200% and 400%; emulate reduced motion and forced colours.
