Accessibility

Overview

TuTuMuch is used by parents in a hurry, grandparents with larger text and families on old phones. Accessibility is built into the Giddy tokens (contrast, motion, targets) and every component page documents role, keyboard, focus, labels, contrast, motion and touch. Automated checks (axe in CI, L2-064) back the commitments below.

Perceivable

  • Text ≥ 4.5:1, UI edges and focus ≥ 3:1, checked for every pair in both themes.
  • Status = colour + icon + text; links underlined.
  • Reflows to 320px; rem sizes.
  • Decorative SVG hidden; meaningful ones labelled.
  • autocomplete on name, email, tel, postal code.

Operable

  • Everything works with a keyboard; dialogs trap focus and close on Esc.
  • One focus ring: 2px --color-focus-ring, 2px offset, on :focus-visible.
  • Sticky bars never cover focus (scroll-padding-top).
  • Targets ≥ 24px, primary mobile ≥ 44px.
  • Toasts ≥ 8 s, pause on hover/focus; errors persist.
  • Skip link on every page.

Understandable

  • Visible labels; “(optional)” in text.
  • Errors name the fix, link from a summary, set aria-invalid.
  • Destructive actions confirm and say what is lost; reversible ones offer Undo.
  • Buying, cancelling and closing an account always ask for an explicit confirmation.
  • Help in the same place on every page.

Robust

  • Native elements first; ARIA follows APG patterns named on each page.
  • Toasts and the reservation timer in live regions.
  • No interactive elements nested in interactive elements.

Testing

  • check_contrast.py and check_design_system.py on every design-system change; axe in CI.
  • Keyboard pass on a page, a dialog and a toast; screen reader pass on the catalog, the sell form and checkout.
  • Zoom 200% and 400%; emulate reduced motion and forced colours.
