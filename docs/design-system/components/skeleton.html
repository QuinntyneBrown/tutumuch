Skeleton

Blush blocks shaped like the content that is loading. Pages never show a spinner while they load.

WCAG 2.2 AAStatus: stableNew in v0.4

Overview

tl-skeleton draws one placeholder block in --color-skeleton (blush). Screens compose them into the shape of the real content: tl-listing-grid shows skeleton cards with a photo, three text lines and a price. The blocks are static: no shimmer, no pulse. The container carries aria-busy="true" and a label; the blocks are aria-hidden.

Anatomy

  1. Photophoto shape, 4:5, --radius-card
  2. Title and brandtext lines at 85% and 45%
  3. Factstext line at 60%
  4. Pricetitle line at 30%

Variants

Shapes: title, text, rect, circle, photo.

Sizes

text is 0.9em tall and title 1.5em, so both follow the surrounding font size. photo keeps 4:5. rect and circle take width and height. Widths are a percentage of the row so lines look like real text of different lengths.

States

Loading listings: the grid has aria-busy="true" and the label “Loading listings”. When the data arrives the real cards replace the blocks in place.

Responsive behaviour

Skeletons live inside the real layout, so they follow it: the skeleton grid has 2, 3 and 4 columns like the listing grid.

Theming

--color-skeleton is blush in light and plum 800 on the plum night.

Both themes

Accessibility

Busy state

The container sets aria-busy="true" and an aria-label (“Loading listings”); every block is aria-hidden. Screen readers hear the label once, not dozens of empty blocks.

Motion

None. Blocks do not shimmer, so there is nothing to stop under reduced motion.

Content

No text inside a skeleton. If loading takes more than a few seconds, the screen shows its error state with a retry, not a longer skeleton.

Do and don't

  • Use tl-spinner only inside a busy control: load more, a submit button, video buffering.
  • Don’t animate skeletons or fade sections in on load.
