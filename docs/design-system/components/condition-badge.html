Condition badge

A pill that names a listing’s condition, coloured by the nearest step of the guideline scale.

WCAG 2.2 AAStatus: stableNew in v0.4

Overview

tl-condition-badge shows the domain condition label on the listing detail page. The domain has five conditions, which are also API values; the labels stay as they are, and the colour follows the guideline scale (New with tags · Like new · Gently loved · Well loved) by nearest step. It is not tl-status, whose colours mean order and listing states, nor tl-size-tag, which is the size.

Anatomy

  1. ContainerPill, --radius-full, 4px × 12px padding
  2. LabelThe domain label, --text-label (14px semibold)
  3. RingWell loved only: 1px inset --color-condition-well-loved-ring (ink/15)

Sizes

One size: 14px semibold label, 28px tall. The badge never stretches; it sits on its own line or beside the size tag.

States

Static. The badge is not interactive and has no hover or focus state.

Both themes

New with tagsNew without tagsUsed - ExcellentUsed - GoodUsed - Fair
New with tagsNew without tagsUsed - ExcellentUsed - GoodUsed - Fair

Responsive behaviour

The badge does not wrap (white-space: nowrap); in a narrow row it moves to the next line with its neighbours.

Theming

Each step has a -bg and -fg token. In dark, New with tags becomes raspberry 400 with plum text, Gently loved a deep raspberry with light text, Well loved the plum surface with a cream ring; Like new stays sunny with ink text.

Accessibility

The label is text, so the colour is never the only signal. Every pair meets 4.5:1:

New with tags
Like new
Gently loved
Well loved

Content

  • Show the domain label exactly: “New with tags”, “New without tags”, “Used - Excellent”, “Used - Good”, “Used - Fair”.
  • Renaming to the four-step scale (New with tags · Like new · Gently loved · Well loved) needs a domain change and is deferred (ADR general/0009).
  • Be honest about condition; never oversell a used item.
